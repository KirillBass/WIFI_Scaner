# Состояние реализации

Текущий релиз: [Version 8](https://github.com/KirillBass/WIFI_Scanner/releases/tag/v8.0.0).
Приложение работает на Windows 10/11 x64. Интерфейс построен на Avalonia, графики на ScottPlot, логика написана на C# и .NET 10.

## Сканирование Wi-Fi

Windows Native Wi-Fi API получает доступные BSS. В «Эфире» показаны SSID, BSSID, RSSI, канал, диапазон, частота и время обнаружения. Доступны поиск, фильтры и сортировка по сигналу. Одинаковые SSID с разными BSSID остаются отдельными точками.

Вендор определяется по встроенной OUI-базе. Стандарт и объявленная защита определяются по Native PHY и Information Elements: 802.11a/b/g/n/ac/ax/be, Wi-Fi 4/5/6/6E/7, Open/WEP/WPA/WPA2/WPA3, Personal/Enterprise, transition и OWE. Шифры и PMF доступны в подробностях. Неизвестные данные не подменяются догадками.

Подробности: [расширение «Эфира»](AIR_CAPABILITIES_REPORT.md).

## Мониторинг сигнала

Мониторинг выбранного BSSID поддерживает интервалы 5, 10, 15, 30 и 60 секунд. Хранятся последние 300 измерений, текущий, средний, минимальный и максимальный RSSI. История остаётся после остановки и очищается отдельно. Переход между вкладками не прерывает мониторинг.

## Анализ каналов

Для диапазонов 2,4/5/6 ГГц доступны таблица нагрузки, график частотного перекрытия и рекомендация канала. Оценка использует RSSI и расстояние между частотами. Ширина 20 МГц является параметром модели, а не измерением реальной ширины каждой BSS. Это оценка Wi-Fi окружения, а не измерение airtime или радиопомех другого типа.

## Устройства локальной сети

Для выбранного Wi-Fi или Ethernet интерфейса отображаются IPv4, подсеть, маска и шлюз. Обнаружение объединяет ICMP и таблицу соседей Windows, ограничивается выбранным интерфейсом и подсетями до 1024 host-адресов. Состояния Online/Unknown/Offline, FirstSeen/LastSeen и история сохраняются между циклами; мониторинг имеет интервалы 10/30/60/120 секунд.

IP и MAC появляются до завершения идентификации. Имя и производитель обновляются асинхронно через LocalComputer, локальный Reverse DNS, mDNS/DNS-SD, NetBIOS, LLMNR, SSDP/UPnP и встроенную OUI-базу. Идентификация не меняет историю присутствия устройства.

В Version 8 добавлены кнопка «Обновить имена», короткий отрицательный кэш, дополнительные mDNS-запросы и прямой mDNS PTR через выбранный интерфейс. Можно сразу начать через Wi-Fi. Ранее полученное имя переносится между Wi-Fi и Ethernet только при совпадении подтверждённой сети, шлюза и MAC устройства. Подсказка показывает источник, интерфейс и время получения имени.

Подробности: [Device Identity](DEVICE_IDENTITY_REPORT.md).

## Подключение и сетевая сессия

Из «Эфира» доступны подключение к Open/WPA2-Personal и выбор адаптера. Для WPA2 требуется известный пароль и поддержка CCMP. Смешанное объявление TKIP+CCMP и групповой TKIP не блокируют подключение с AES/CCMP. Используются временный профиль, уведомления Windows и отдельное ожидание IPv4.

Общая сессия содержит SSID, фактический BSSID, адаптер, IPv4, подсеть и шлюз. После готовности IPv4 открывается «Сетевой аудит». Пароль не сохраняется в настройках или журналах. Отключение и смена сети отменяют операции прежней сессии.

Подробности: [Wi-Fi Connection](WIFI_CONNECTION_REPORT.md).

## Аудит TCP-портов и служб

Аудит запускается сразу для снимка найденных устройств текущей сессии, шлюза и, по выбору, этого ПК. Доступны профили «Быстрый» (28 портов), «Стандартный», «Полный» и «Пользовательский», настройка параллелизма и тайм-аута. Используется TCP Connect с привязкой к выбранному интерфейсу.

Открытые порты появляются сразу, затем асинхронно уточняются служба, продукт, версия, достоверность и доказательство определения. HTTP/HTTPS, SSH, FTP, RDP и SMB распознаются по ответам сервера. Неизвестная служба остаётся Unknown; номер порта сам по себе не подтверждает протокол. Поиск, фильтры, подробности, счётчики и остановка доступны на одной странице.

При отключении или смене сети аудит отменяется, результаты прежней сессии очищаются. Закрытие приложения ожидает завершения фоновых операций.

Подробности: [Network Audit](NETWORK_AUDIT_REPORT.md).

## Структура и ограничения

Solution содержит три проекта: Core с моделями и алгоритмами, Infrastructure.Windows с Windows API и сетевыми сервисами, App с Avalonia, MVVM и DI. Общие сервисы сканирования, мониторинга и сетевой сессии используются всеми страницами. Новые возможности встроены в существующие проекты.

Данные обрабатываются локально. Внешние API идентификации MAC/IP/hostname не используются. Имя доступно только если устройство или локальная сеть публикует его. Private MAC, сон, firewall, VLAN и Client Isolation ограничивают обнаружение и идентификацию. Тайм-аут TCP не означает закрытый порт. Аудит не выполняет вход в службы или подбор паролей. В текущем этапе реализован TCP; UDP-аудит и IPv6 не включены.
