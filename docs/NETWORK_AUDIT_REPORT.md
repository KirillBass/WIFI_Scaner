Включено в Version 8. Расширение существующего Milestone 5 в прежнем solution.

## 2. Формирование списка целей

`AuditTargets.Create` проверяет Ready-сессию, совпадение `LocalNetworkInfo.HasSameContext` у discovery и текущей сессии и непустой список найденных устройств. Учитываются все известные узлы подходящей подсети, независимо от фильтра/выделения строки в интерфейсе. Дубликаты удаляются по IPAddress. Network/broadcast, loopback, APIPA, multicast и адреса другой подсети отклоняются существующим `SubnetCalculator`.

Автоматически добавляются собственный IPv4 (если установлен флажок) и шлюз, когда он принадлежит подсети. Перед началом соединений `ILocalNetworkService.IsCurrentAsync` дополнительно проверяет фактический интерфейс. Цели копируются в неизменяемый список; сеть не перебирается заново. Пустое/устаревшее discovery вызывает сообщение «Сначала обновите список устройств текущей сети».

## 3. Профили портов

| Профиль | Порты |

| Quick / Быстрый | 21,22,23,25,53,80,110,135,139,143,389,443,445,465,587,636,993,995,1433,3306,3389,5432,5900,5985,5986,8000,8080,8443 |

## 4. Concurrency и таймауты

`Parallel.ForEachAsync` лениво берёт пары порт/цель: один общий лимит работников для проверки TCP и определения служб. По умолчанию 64, разрешено 1–128. Один работник держит максимум одно TCP-соединение; перед fallback старое закрывается. Миллионы заранее созданных Tasks отсутствуют.

Первичный TCP Connect - 650 мс по умолчанию, настройка в интерфейсе 100–10000 мс. Повторное подключение отдельной protocol probe ограничено 650 мс и её общим дедлайном. `NetworkAuditOptions`: приветствие 150 мс/4096 байт, отдельный detector 1500 мс, общий бюджет определения одной службы 6000 мс. HTTP headers и бинарный кадр ограничены 64 KiB. Настройки службы централизованы в DI; пользовательские поля относятся к первичной TCP-проверке.

## 5. TCP Connect scan

IPv4 `Socket` привязывается к собственному IPv4 выбранного интерфейса. Переиспользуется `IdentitySocketScope`: Windows IP_UNICAST_IF и TTL=1. Адрес назначения проверяется на принадлежность подсети перед соединением. Используется обычный `ConnectAsync` с linked CancellationToken и дедлайном; административные права не нужны.

Успех даёт Open и поток NetworkStream; ConnectionRefused - Closed; timeout - Timeout; недоступный маршрут/адрес/сеть - Unavailable; прочие ошибки - Error с кратким SocketError. Поток принадлежит `PortScanConnection` и освобождается при отмене/ошибке/завершении. Первое активное определение по возможности использует то же подключение. Повторное подключение требуется после неподходящей/израсходованной пробы.

## 6. Реализованные service detectors

Независимые классы: `HttpServiceDetector`, `HttpsServiceDetector`, `SshServiceDetector`, `FtpServiceDetector`, `RdpServiceDetector`, `SmbServiceDetector`, `GenericBannerServiceDetector`.

Сначала engine ограниченно читает приветствие для SSH/FTP/SMTP. Затем пробует подходящий по порту RDP/SMB/HTTP/TLS; HTTP и TLS также доступны как fallback для неизвестного открытого порта. Отсутствие ответа/некорректный ответ отдельного обработчика не прерывает весь аудит. До успешного TCP Connect обработчики не запускаются.

## 7. Подтверждение протоколов и продуктов

HTTP: валидная status line HTTP/1.0 или HTTP/1.1 и завершённые headers после одного `HEAD /`. По фактическому Server распознаются Microsoft-IIS → Microsoft IIS, Apache и nginx; версия только из этого заголовка. Без Server протокол подтверждается, продукт остаётся неизвестным. Redirect, cookies, авторизация и тело страницы не обрабатываются.

HTTPS: SslStream handshake с публичными Subject/SAN/Issuer, TLS и ALPN; затем HTTP HEAD. При подтверждённом TLS без HTTP результат TLS. Самоподписанный сертификат допустим только для fingerprint; в подробностях явно написано, что доверие не подтверждается. Проверка отзыва и загрузка сертификатов/AIA отключены; внешние сервисы не вызываются.

SSH: корректная identification string SSH-2.0/1.99, ограничение длины/NUL. OpenSSH/Dropbear/libssh и версия извлекаются только из software token. FTP: завершённое приветствие 220; известные FTP-продукты/явная FTP-сигнатура дают High, общий 220 на FTP-порту - Medium. ESMTP/SMTP не выдаётся за FTP. Поддерживается баннер Microsoft FTP Service, вход USER/PASS не выполняется. Generic распознаёт SMTP только при фактическом 220 SMTP/ESMTP.

RDP: TPKT + X.224 + RDP_NEG_REQ; валидируется RDP_NEG_RSP либо RDP_NEG_FAILURE, длина и допустимые коды. До TLS/NLA/аутентификации RDP-клиента алгоритм не доходит. Обычный X.224 без RDP negotiation не считается подтверждением. Производитель/версия ОС по этому обмену не угадываются. Формат взят из [Microsoft MS-RDPBCGR](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpbcgr/b2975bdc-6d56-49ee-9c57-f2ff3a0b6817).

SMB: только прямой TCP NEGOTIATE на 445 с предложением 2.0.2/2.1/3.0/3.0.2. Проверяются signature, размеры, status, command, server flag, MessageId, выбранный диалект и границы security buffer. Выводится фактически согласованный SMB2/SMB3 и диалект; это не максимальная версия сервера. SESSION_SETUP, вход, shares и файлы не запрашиваются. Формат ответа: [Microsoft MS-SMB2](https://learn.microsoft.com/en-us/openspecs/windows_protocols/MS-SMB2/63abf97c-0d09-47e2-88d6-6bfa552949a5).

## 8. Unknown, timeout и firewall

Открытый порт без подтверждённого ответа остаётся Unknown с неизвестными продуктом/версией. Номер порта выбирает пробу, не подтверждает службу. Ошибка/таймаут detector не меняет подтверждённый Open на Closed. Closed/Timeout/Unavailable/Error отражаются отдельными счётчиками; таблица содержит открытые порты.

Интерфейс и README поясняют: доступность наблюдается с узла, выполняющего аудит; firewall, VLAN, Client Isolation, сон и изменённые/скрытые баннеры ограничивают результат. Сам timeout не доказывает отсутствие службы.

## 9. Прогресс и Stop

Публикуются подготовка, сканирование TCP/определение служб, завершающая стадия определения и окончательный статус. Счётчики: завершённые/все узлы, проверенные/плановые порты, Open, Closed, Timeout, Unavailable, Error, подтверждённые службы и elapsed.

Первая открытая строка публикуется сразу как Unknown; следующие обновления группируются примерно до одного снимка за 150 мс. Проверка контекста/elapsed также обновляет снимок раз в секунду. Уточнение службы заменяет строку с тем же IP/портом; обновления попадают в ObservableCollection только через UI thread. Фильтры не влияют на список целей.

Stop отменяет linked token, прекращает выдачу работ, отменяет Connect/Read/Write/handshake и ждёт работников. Частичные результаты текущей сети сохраняются. Отключиться можно во время аудита. Закрытие основного окна ждёт завершения отмены.

## 10. Смена NetworkSession

Сервис подписан на существующий `INetworkSessionService.Updated`; ID, Ready-состояние и контекст интерфейса сверяются перед работой и после определения. Отдельная проверка фактического интерфейса выполняется раз в секунду. Смена сети/отключение отменяет общий токен, очищает текущие строки и показывает «Аудит остановлен: сеть изменилась».

Каждая строка хранит SessionId; отдельные запуски имеют AuditId. Очередь UI защищена монотонной Version и сверкой SessionId/Ready, поэтому поздний снимок не возвращает старые строки. Новый запуск заменяет результаты целиком.

## 11. Оставшиеся ограничения

- Аудит ограничен TCP и существующим discovery; UDP, произвольный subnet sweep, crawler, эксплуатация, обход firewall и вход по учётным данным отсутствуют.
- RDP пробуется на 3389/3390, SMB только прямой TCP 445. SMB1, NetBIOS Session Service 139 и отдельное согласование SMB3.1.1 не реализованы; серверы с требованием исключительно 3.1.1 могут остаться Unknown.
- Версия SMB - согласованный диалект, а не гарантированная максимальная поддерживаемая версия; RDP/SMB сами по себе не подтверждают Windows/Microsoft/Samba.
- HTTP/TLS могут остаться Unknown при обязательном hostname/SNI, отсутствии ответов или нестандартном протоколе. Server/баннер - заявление сервера, которое можно скрыть или изменить.
- Общий FTP 220 на 21 без явного названия продукта имеет Medium из-за сходства с SMTP; неизвестные баннеры не публикуются целиком.
- Результаты и имена целей - текущий снимок в памяти, без базы истории; полный профиль больших сетей занимает время и память пропорционально числу найденных открытых портов.
- Self-signed fingerprint не является проверкой доверия; службы, слушающие только loopback, не обязаны быть видимы по IPv4 интерфейса.
